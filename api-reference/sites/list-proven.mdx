---
title: "List proven sites"
description: "The websites where skills keep working for real people, most used first. No key needed."
api: "GET https://api.valendata.com/v1/sites/proven"
---

A site is **proven** when at least one skill on it keeps working: in the last 30 days it worked at least 3 times, and at least half of its runs worked. See [Proven sites](/guides/when-a-site-does-not-work#proven-sites).

No key needed.

<ParamField query="q" type="string">
  Only sites whose domain contains this text, for example `airbnb`.
</ParamField>

<ParamField query="limit" type="integer" default="50">
  Most sites to return.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  How many sites to skip. To get the next page, pass the number of sites you already have.
</ParamField>

<ResponseField name="total" type="integer">
  How many proven sites match, across all pages.
</ResponseField>

<ResponseField name="sites" type="object[]">
  One page of proven sites.

  <Expandable title="site">
    <ResponseField name="domain" type="string">The site, such as `airbnb.com`.</ResponseField>
    <ResponseField name="skills" type="integer">Skills that ran on it in the last 30 days.</ResponseField>
    <ResponseField name="users" type="integer">People who ran those skills.</ResponseField>
    <ResponseField name="runs_30d" type="integer">Runs in the last 30 days.</ResponseField>
    <ResponseField name="success_rate" type="number">Share of those runs that worked.</ResponseField>
    <ResponseField name="last_success_at" type="string | null">When a run on it last worked.</ResponseField>
    <ResponseField name="status" type="string">Always `proven` here.</ResponseField>
  </Expandable>
</ResponseField>

MCP tool: `site_status` checks one site. See [Get a site](/api-reference/sites/get).

<RequestExample>

```bash curl
curl "https://api.valendata.com/v1/sites/proven?q=airbnb&limit=50&offset=0"
```

</RequestExample>
