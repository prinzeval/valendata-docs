---
title: "Get a site"
description: "How skills are doing on one website right now: proven, failing, or not proven yet. No key needed."
api: "GET https://api.valendata.com/v1/sites/{domain}"
---

Check a site before you build a skill for it, or after a run on it fails. No key needed. What the answers mean, and how to ask us to fix a site, is in [When a site does not work](/guides/when-a-site-does-not-work).

<ParamField path="domain" type="string" required>
  The site, such as `airbnb.com`. A full address works too, such as `https://www.airbnb.com/rooms/123`; only its domain is used. `www.`, `m.`, and other subdomains are dropped, so `newyork.craigslist.org` is `craigslist.org`.
</ParamField>

<ResponseField name="domain" type="string">
  The site's domain.
</ResponseField>

<ResponseField name="status" type="string">
  `proven`, `failing`, or `unproven`. What each means is in [Check one site](/guides/when-a-site-does-not-work#check-one-site).
</ResponseField>

<ResponseField name="skills" type="integer | null">
  Skills that ran on it in the last 30 days.
</ResponseField>

<ResponseField name="users" type="integer | null">
  People who ran those skills.
</ResponseField>

<ResponseField name="runs_30d" type="integer | null">
  Runs in the last 30 days.
</ResponseField>

<ResponseField name="success_rate" type="number | null">
  Share of those runs that worked.
</ResponseField>

<ResponseField name="last_success_at" type="string | null">
  When a run on it last worked.
</ResponseField>

<ResponseField name="open_request" type="object | null">
  The open [site request](/api-reference/sites/create-request) for this site: its `id`, `votes` (how many people asked), and `status`. It shows once at least 3 people have asked, so one person's ask is never pointed to. `null` until then.
</ResponseField>

`skills`, `users`, `runs_30d`, `success_rate`, and `last_success_at` are `null` unless the site is `proven` or `failing`. Which sites are shown is in [Check one site](/guides/when-a-site-does-not-work#check-one-site).

MCP tool: `site_status`, with `url_or_domain`.

<RequestExample>

```bash curl
curl "https://api.valendata.com/v1/sites/example-shop.com"
```

</RequestExample>
