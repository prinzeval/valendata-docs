The fields you will use most:

| Field | What it is |
| --- | --- |
| `input_schema` | JSON Schema for the inputs: each input's `type`, `description`, `default`, and examples. `required` lists the ones you must send. Unknown inputs are refused. An input that acts as a `request` or a `filter` also has `x-acts-as` and `x-where` (see [Inputs](/concepts/skills#inputs)). Its `examples` include the values the site is known to take, and `x-known-values-count` says how many there are. |
| `parameters` | Each input, with the values the site is known to accept (`known_values`) and the ones it would not take (`refused_values`). See [Values an input takes](/guides/run-a-skill#values-an-input-takes). A mapped input also has `acts_as` and `where`. |
| `output_json_schema` | JSON Schema for the run result, including each row. |
| `output_types` | Each output field's type, such as `{"yes_price": "chance", "end_date": "datetime"}`. `null` on a skill made before types. See [Output field types](/concepts/skills#output-field-types). |
| `available_inputs` | Every input the skill can take, each on or off. See [Available inputs](#available-inputs). |
| `reliability` | Success rate, runs, and repairs over the last 20 runs, and the last failure kind. |
| `price` | What a run usually costs, before you run it. See [Price](#price). |
| `proof` | A public skill's [track record](/guides/use-the-marketplace#track-record) on real runs, its own and its marketplace copies': how many of the last 20 worked, typical run time, rows and credits, when it last worked and was last checked, and a status. The fields are listed under [Find a skill for a task](/api-reference/marketplace/search). `null` for a private skill. |
| `recipe_version`, `pinned_recipe_version` | The live [version](/concepts/keeping-skills-working#versions), and the pinned one (or `null`). |
| `fast_path` | A short description of the skill's [fast path](/concepts/keeping-skills-working#fast-path), or `null`. A skill built on the site's [open API](/guides/create-a-skill#open-apis-first) reads like `reads the site's public API (gamma-api.polymarket.com/markets), no browser, ~0.8s`. One that makes a second call per row adds `list + detail (one more call per row: gamma-api.polymarket.com/markets/{id})`. |
| `fast_path_detail_endpoint` | For a skill built on an open API that makes one more call per row for fields its list does not carry ([list plus detail](/guides/create-a-skill#list-plus-detail)): that call, as host and path, such as `boards-api.greenhouse.io/v1/boards/figma/jobs/{id}`. Otherwise `null`. |
| `reads_by` | How the skill reads its data. `main` is the way it tries first, and `backups` the ways it falls back to, in order. Each has `kind`, `label`, `where`, `where_label`, and `typical_seconds` (how long a run that way usually takes, or `null`). The names are in [How a run got its data](/concepts/runs#how-a-run-got-its-data). |
| `api_endpoint`, `runs_endpoint`, `versions_endpoint` | The routes to run it and see its versions. |
| `site_domain`, `endpoint_name` | The website it works on and its name there, for calling it through its [Site API](/concepts/site-apis). |

A public skill needs no key. Anyone may read it, but runs only their own copy: [clone it](/api-reference/skills/clone) first. A private skill returns `404` to anyone who may not run it.

MCP tool: `get_skill`.

## Available inputs

`available_inputs` lists every input the skill can take, worked out on its own when the skill is created or changed. What it looks for is in [Available inputs](/concepts/skills#available-inputs). Only the skill's owner and its workspace see it; for anyone else it is `null`.

| Field | What it is |
| --- | --- |
| `computing` | `true` while the list is being worked out. Read the skill again in a minute. |
| `computed_at` | When the list was last worked out. |
| `recipe_version` | The [version](/concepts/keeping-skills-working#versions) it was worked out for. |
| `source` | Where the rows come from: `browser`, `api`, `feed`, or `platform:<name>`, such as `platform:shopify`. |
| `inputs` | One entry per input. See below. |
| `explanation` | What was found, in plain words. |

Each entry in `inputs`:

| Field | What it is |
| --- | --- |
| `name`, `type`, `description`, `required`, `default` | The input as it would be added. |
| `acts_as`, `where` | How it acts on the data. See [Update a skill](/api-reference/skills/update#inputs). |
| `example` | A value that passed the check. |
| `known_values` | Values the site is known to take. |
| `verified`, `check` | Whether it was tried for real, and what the try saw, such as `keeps 4 of 20 sample row(s) for 'Engineering'`. |
| `on` | `true` when the skill has this input now. `input_name` is the name it has it under. |
| `can_turn_off`, `off_note` | For an input that is on: whether `inputs.remove` takes it, and why not. |

```json
"available_inputs": {
  "computing": false,
  "computed_at": "2026-10-22T09:14:03Z",
  "recipe_version": 4,
  "source": "platform:greenhouse",
  "inputs": [
    {
      "name": "department",
      "type": "string",
      "acts_as": "filter",
      "where": {"kind": "one_of", "fields": ["department"]},
      "example": "Engineering",
      "known_values": ["Engineering", "Sales", "Design"],
      "verified": true,
      "check": "keeps 4 of 20 sample row(s) for 'Engineering'",
      "on": false
    }
  ],
  "explanation": "Greenhouse lists every job at once, so department and location are filters."
}
```

To turn an entry on, send it as it is in `inputs.add` to [Update a skill](/api-reference/skills/update#inputs). To turn it off, send its `input_name` in `inputs.remove`.

## Price

A run is billed what it uses, and never less than the skill's base fee. `price` says what a run usually costs:

| Field | What it is |
| --- | --- |
| `estimate_credits` | What a run usually costs: the median of its last 20 successful runs, never below the base fee. Before any run, the base fee. |
| `estimate_usd` | `estimate_credits` in US dollars. |
| `base_credits` | The least a run costs: the base fee. |
| `typical_credits` | The median of the recent successful runs, or `null` before any. |
| `recent_runs` | How many recent successful runs `typical_credits` is read from. |
| `basis` | `typical_of_recent_runs`, or `base_price` before any run. |

What each run actually cost is its `credits_charged`. See [Credits](/concepts/credits).
