---
title: "Import an Apify actor"
description: "Bring an Apify actor to Valendata: get the equivalent call, or create a skill that does the same."
openapi: "POST /v1/import/apify"
---

`actor_url_or_id` is the actor's apify.com URL or its id, such as `compass/crawler-google-places`. `input` is the run input you use today. `kind` in the answer says what happened:

| `kind` | What happened |
| --- | --- |
| `alias` | The actor already runs on Valendata. You get `apify_compatible_call` (the same input, under `/apify/v2`) and `valendata_call` (your input translated). Nothing is created. |
| `skill` | You already have a skill for it. `skill_slug` is that skill. |
| `creation` | A skill is being created from the actor's public description, with its output fields as the new skill's columns. Poll `status_url`, as with [Create a skill](/api-reference/skills/create). It costs the same. Pass `start_url` when the input names no page: without one, the call answers `422`. |

How the Apify-compatible API works: [Switch from Apify](/guides/switch-from-apify).

Needs `skills:read` for an alias, `skills:write` to create a skill.
