title: "Workspaces"
description: "A workspace holds skills, workflows, browser profiles, and Vault credentials for one team or client, with roles and a shared credit balance."
---

A **workspace** holds your skills, workflows, browser profiles, and Vault credentials. Each of these belongs to exactly one workspace. You invite people to a workspace, and everyone in it runs on the workspace owner's credit balance. Use separate workspaces to keep projects, clients, or environments apart.

## What lives inside a workspace

<CardGroup cols={2}>
  <Card title="Skills" icon="bolt">
    Skills belong to the workspace they were made in. Another workspace cannot see or run them.
  </Card>

  <Card title="Workflows" icon="diagram-project">
    Workflows and their schedules belong to the workspace. A workflow can only use skills from the same workspace.
  </Card>

  <Card title="Browser profiles" icon="browser">
    Signed-in browser sessions belong to the workspace they were made in. Other workspaces cannot use them.
  </Card>

  <Card title="API keys" icon="key">
    API keys belong to the person who made them, not to a workspace. A private skill can only be run with its owner's key.
  </Card>

  <Card title="Vault" icon="lock">
    Vault credentials, such as webhook tokens, database passwords, and API keys for other services, belong to the workspace. Only steps running in it can use them.
  </Card>

  <Card title="Credit balance" icon="coins">
    Every run in the workspace, by any member or schedule, is paid from the owner's balance, not the member's.
  </Card>
</CardGroup>

## Create a workspace

In the sidebar, click your current workspace name to open the switcher. At the bottom, click **New workspace**, enter a name, and click **Create workspace**. The dashboard reloads in the new, empty workspace.

<Tip>
  If you work for several clients, make one workspace per client. Each client's skills, workflows, and credentials then stay separate.
</Tip>

## Switch workspaces

Click your workspace name in the sidebar. The list shows every workspace you belong to and your role in each. Click one to switch. The dashboard reloads with only that workspace's skills, workflows, and settings.

## Manage team members

Manage members on the **Team** page in the sidebar. There you can see members, send invites, change roles, and set spend caps.

<Steps>
  <Step title="Open the Team page">
    Click Team in the sidebar.
  </Step>
  <Step title="Invite a member">
    Enter their email address, pick a role, and send the invite. They get an email with a link to accept. If they have no Valendata account, they create one first.
  </Step>
  <Step title="Set a spend cap (optional)">
    After a member joins, you can set a monthly credit cap for them. Once they reach it, their runs stop being charged to the workspace for the rest of the month. Leave it empty for no cap.
  </Step>
</Steps>

## Roles

| Role | What they can do |
| :-- | :-- |
| **Owner** | Full access. Manages members, billing, and all resources. Only the Owner can delete a workspace. |
| **Admin** | Can create, edit, and delete skills, workflows, browser profiles, and Vault credentials. Can invite and remove members. Cannot manage billing. |
| **Member** | Can create and run skills and workflows. Cannot delete resources created by others or manage members. |
| **Viewer** | Read-only access. Can view skills, workflows, and run history but cannot trigger runs or create resources. |

## Move a skill to another workspace

To move a skill to another workspace, open the **Skills** page, open the skill's action menu, and choose **Move to Workspace**. Pick the workspace to move it to. Only workspaces where you are an Admin or Owner are listed. The skill leaves the old workspace at once.

<Warning>
  Moving a skill removes it from the source workspace. Any schedules or workflow steps that reference it there will stop working. Update those before moving.
</Warning>

## Shared credit balance

Every run in a workspace draws from the workspace owner's credit balance, monthly plan credits and purchased credits alike. When a member starts a run or a schedule fires, the credits come from the owner's balance. The owner can set a monthly spend cap for each member on the **Team** page.
