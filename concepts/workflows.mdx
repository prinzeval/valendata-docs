---
title: "Workflows"
description: "A workflow chains steps together: skills, code, HTTP calls, and exports. It has its own inputs and returns the rows of its last step."
---

A **workflow** runs several steps in order and passes data from one to the next. For example: run a skill that lists competitor prices, keep only the ones below your price, then post them to Slack.

## Steps

| Step | What it does |
| --- | --- |
| **Skill** | Runs one of your [skills](/concepts/skills) with inputs you set. |
| **Agent** | A browser agent does a task you describe, without a saved skill. |
| **Code** | Runs Python in a sandbox to clean, join, or reshape rows. |
| **HTTP** | Calls any URL (`GET`, `POST`, `PUT`, `DELETE`). Can use a credential from the **Vault**, which is never shown in run history. |
| **Transform** | Map, filter, pick, or wrap rows, with no outside calls. |
| **Integration** | Reads from or writes to Slack, Gmail, Notion, Google Sheets, or Postgres. |
| **Connected App** | Runs one tool of a [connected app](/concepts/connected-apps): reads rows from your Gmail, calendar, CRM, or any app you connected, or acts in it. |

## Inputs

Every workflow starts with an **API trigger**. It lists the workflow's inputs, each with a name, a type, and an optional default. Steps use an input by writing `{{inputs.<name>}}`. Scheduled runs use the defaults.

The inputs are the workflow's **contract**, just like a skill's. Callers and AI assistants read it to know what to send.

## Passing data between steps

Any step setting can use the output of an earlier step:

| Reference | What it gives you |
| --- | --- |
| `{{inputs.search_term}}` | A workflow input. |
| `{{step_1.output.items}}` | The `items` field of step `step_1`'s output. |
| `{{step_2.output.0.price}}` | The `price` of the first row of `step_2`. |

When a whole setting is a single reference, the value keeps its type, so `{{inputs.limit}}` in **Max results** becomes the number `3`. Inside longer text it is pasted in as text.

## What a workflow returns

A workflow run returns the rows of its last step as `outputs`. If several steps end the workflow, `outputs` has one set of rows per final step, keyed by step name. Each step's own status and row count are in the run too. See [Runs](/concepts/runs).

## Ways to start a workflow

The same ways as a skill: the **Run** button, the API, an AI assistant (each workflow is a tool named `workflow_<slug>`), or a schedule. See [Build a workflow](/guides/build-a-workflow).

## Cost

A workflow run is charged a base fee or the sum of its steps' costs, whichever is higher, never both. Skill, agent, and code steps use credits. HTTP and transform steps do not. See [Credits](/concepts/credits).
